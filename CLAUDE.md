## Overview

This is the **InSpire** repository - an implementation of Vision-Language-Action models with intrinsic spatial reasoning for robotics. The project implements VLA models based on OpenVLA architecture with a novel InSpire approach that improves spatial reasoning by appending spatial reasoning questions ("In which direction is the [object] relative to the robot") to language instructions.

### Current Development Goal

The primary objective is to **train linear probes on VLA trajectory data** to analyze the learned representations. **All core data collection is now fully implemented and working.** The system currently collects and stores:

1. ✅ **Hidden states**: From every layer of the VLA model during action prediction for each timestep (IMPLEMENTED)
2. ✅ **Action outputs**: Low-level control actions (7-dimensional robot control vectors) generated by the VLA for each timestep (IMPLEMENTED)
3. ✅ **Vision encoder outputs**: Raw patch features from the vision backbone (DINOv2/CLIP/SigLIP etc.) for each timestep (IMPLEMENTED)
4. **Simulator states**: Object positions, contact states, and other simulator metadata for future annotation (PENDING)
5. **Image reconstruction traces**: Efficient references to regenerate images from simulator (stored separately due to size) (PENDING)

The data is stored in HDF5 format with hierarchical structure:
- **Actions**: `/task_{id}/episode_{id}/timesteps/actions` - Array of shape `[timesteps, 7]` containing robot control vectors
- **Vision Features**: `/task_{id}/episode_{id}/timesteps/vision_features` - Array of shape `[timesteps, num_patches, vision_dim]` containing raw vision encoder outputs
- **Hidden states**: `/task_{id}/episode_{id}/timesteps/hidden_states/layer_{layer_idx}/timestep_{timestep}/generation_step_{step}` - Hidden state arrays for each autoregressive generation step
- **Metadata**: Episode-level metadata including success status, task description, and episode identifiers

## Key Components

### Core Architecture
- **prismatic/**: Core VLA model implementation based on OpenVLA
  - `conf/vla.py`: VLA model configurations for different datasets and training setups
  - `models/`: VLM model architectures (vision-language-action models)
  - `vla/`: VLA-specific modules and action tokenizers
- **LIBERO/**: Robotics simulation environment and benchmarking suite
- **vq_bet_official/**: VQ-BET (Vector Quantized Behavior Transformer) implementation

### Training and Evaluation
- **vla_scripts/**: Main training and evaluation scripts
  - `train.py`: Standard VLA training 
  - `train_vqa.py`: InSpire training with spatial reasoning VQA
  - `parallel_libero_evaluator.py`: Multi-GPU evaluation on LIBERO tasks with trajectory data collection
  - `data_collecting_vla.py`: Wrapper around OpenVLA model for hidden states collection during evaluation
  - `trajectory_data_collector.py`: HDF5 data collector for storing trajectory hidden states 
  - `load_trajectory_data.py`: Utilities for loading and processing collected trajectory data for linear probing
  - `combine_trajectory_files.py`: Combines trajectory data files from multiple parallel processes
- **scripts/**: Data preprocessing and utility scripts
  - `parallel_libero_dataset_regenerator.py`: Clean and preprocess LIBERO datasets
  - `annotate_data.py`: Add spatial annotations to real-world data

### Datasets
- **rlds_dataset_builder/**: TensorFlow dataset builders for LIBERO tasks
- LIBERO simulation tasks: libero_90, libero_10, libero_goal, libero_object, libero_spatial

## Trajectory Data Collection Pipeline ✅ FULLY IMPLEMENTED
The trajectory data collection system is now fully functional for collecting hidden states, actions, and vision encoder outputs from VLA model evaluation:

### Implementation Details:
- **DataCollectingVLA** (`vla_scripts/data_collecting_vla.py`): Wrapper around OpenVLA that captures hidden states, actions, and vision encoder outputs during `predict_action()` calls
- **TrajectoryDataCollector** (`vla_scripts/trajectory_data_collector.py`): HDF5-based storage system with process-safe parallel writing for all data types
- **ParallelLiberoEvaluator** modifications: Added `--collect-trajectory-data` flag to enable data collection mode
- **File combination**: `vla_scripts/combine_trajectory_files.py` merges data from multiple parallel processes

### Data Structure:
```
trajectory_data_<suite>.h5
├── task_0/
│   ├── episode_0/
│   │   ├── metadata (attrs: success, task_description, num_timesteps, libero_task_id, libero_episode_id)
│   │   └── timesteps/
│   │       ├── timestep_ids (array: [0, 1, 2, ...])
│   │       ├── actions (array: [timesteps, 7])  # Robot control vectors
│   │       ├── vision_features (array: [timesteps, num_patches, vision_dim])  # Vision encoder outputs
│   │       └── hidden_states/
│   │           ├── layer_0/
│   │           │   ├── timestep_0/
│   │           │   │   ├── generation_step_0/  # Full input processing
│   │           │   │   ├── generation_step_1/  # 1st action token
│   │           │   │   └── ...generation_step_N/  # Nth action token
│   │           │   └── timestep_1/...
│   │           └── layer_N/...
│   └── episode_1/...
└── task_1/...
```

### Usage:
1. **Collection**: Run evaluation with `--collect-trajectory-data --trajectory-data-save-path <dir> --max-total-trajectories <N>`
2. **Loading**: Use `load_trajectory_data.py` with filtering by layers, tasks, episodes, generation steps
3. **Analysis**: Extract flattened hidden states, actions, and vision features for linear probe training

- ✅ **Complete Data Collection**: Captures hidden states, 7D robot actions, AND vision encoder outputs
