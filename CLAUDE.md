## Overview

This is the **InSpire** repository - an implementation of Vision-Language-Action models with intrinsic spatial reasoning for robotics. The project implements VLA models based on OpenVLA architecture with a novel InSpire approach that improves spatial reasoning by appending spatial reasoning questions ("In which direction is the [object] relative to the robot") to language instructions.

### Current Development Goal

**The primary objective is to implement and run linear probing experiments on VLA trajectory data to analyze the learned representations.** All core data collection, reconstruction, and loading systems are fully implemented and production-ready. The focus is now on implementing the four probing experiments specified in `probing/README.md`:

1. **Experiment 1**: [Hidden state] -> actions - Linear regression probes for every layer's hidden states
2. **Experiment 2**: [Vision encoder outputs] -> actions - Linear regression probes for vision patch features  
3. **Experiment 3**: [Hidden state] -> visual concepts - Using simulator-derived visual/visual-language concepts
4. **Experiment 4**: [Vision encoder outputs] -> visual concepts - Using simulator-derived visual/visual-language concepts

Each experiment includes three baselines: Normal (original data), Randomized pairs (shuffled trajectories), and Noise baseline.

### Available Data Types

The system provides complete multi-modal trajectory datasets stored in HDF5 format:

1. ✅ **Hidden states**: From every layer of the VLA model during action prediction for each timestep
2. ✅ **Action outputs**: 7-dimensional robot control vectors generated by the VLA for each timestep  
3. ✅ **Vision encoder outputs**: Raw patch features from the vision backbone (DINOv2/CLIP/SigLIP etc.) for each timestep
4. ✅ **Images**: Can be reconstructed using ultra-efficient minimal clues (3 integers per episode) via LIBERO
5. ✅ **Simulator states**: Object positions, robot joint states, end-effector poses, and complete physics metadata (reconstructable)

### Data Structure (HDF5 Format)
```
trajectory_data_<suite>.h5
├── task_0/episode_0/
│   ├── metadata/  # Group with attributes
│   │   ├── @success: bool
│   │   ├── @task_description: str  
│   │   ├── @num_timesteps: int
│   │   ├── @libero_task_id: int
│   │   ├── @libero_episode_id: int
│   │   ├── @img_task_id: int        # Image reconstruction clues (3 integers per episode)
│   │   ├── @img_episode_id: int
│   │   └── @img_env_seed: int
│   └── timesteps/
│       ├── timestep_ids (array: [0, 1, 2, ...])
│       ├── actions (array: [timesteps, 7])  # Robot control vectors
│       ├── vision_features (array: [timesteps, num_patches, vision_dim])  # Vision encoder outputs  
│       └── hidden_states/
│           └── layer_N/
│               └── timestep_T/
│                   ├── generation_step_0/  # Full input processing  
│                   ├── generation_step_1/  # 1st action token
│                   └── generation_step_S/  # Sth action token
```

### Data Loading for Linear Probing
Use `vla_scripts/legacy/load_trajectory_data.py` (the correct loader) which provides:
- **Data Structure**: Nested dictionaries organized by task_id/episode_id for easy access
- **Hidden States**: `dataset['hidden_states'][layer_idx][task_id][episode_id][timestep_id][generation_step]` -> np.ndarray  
- **Actions**: `dataset['actions'][task_id][episode_id]` -> np.ndarray of shape [timesteps, 7]
- **Vision Features**: `dataset['vision_features'][task_id][episode_id]` -> np.ndarray of shape [timesteps, num_patches, vision_dim]
- **Flattening Functions**: `get_layer_data_flat()`, `get_actions_data_flat()`, `get_vision_features_data_flat()` for ML-ready arrays
- **Binary Classification Support**: Hidden states and vision features can predict both continuous (regression) and binary (classification) targets
